# BUG-018: No standard security headers are sent

| Field | Value |
|---|---|
| Severity | Minor |
| Priority | Medium |
| Module | Security |
| Origin | Genuine |
| Status | Open |
| Found in | https://www.saucedemo.com, Chrome (Chromium), 2026-11-05 |
| Test user | `n/a (any request)` |
| Failed test cases | TC-069 |

## Steps to reproduce
1. Run: curl -I https://www.saucedemo.com/
2. Read the response headers

## Expected result
Strict-Transport-Security, Content-Security-Policy, X-Content-Type-Options, X-Frame-Options (or frame-ancestors) and Referrer-Policy are present.

## Actual result
Only Server (GitHub.com) and Cache-Control are sent; none of the five security headers. Plain HTTP does redirect to HTTPS (301), which is good.

## Evidence
Browser alert or behaviour with no screenshot; reproduce with the steps above.

> Impact if real: weaker protection against clickjacking, content sniffing and script injection. The site is on a static host, which may limit what can be set. Logged as if found in a real product. The practice shop has no server behind its login, so this is how it is built, but a real shop with this behaviour would have the stated impact.
