# BUG-020: The cart cannot be reached or opened with the keyboard

| Field | Value |
|---|---|
| Severity | Critical |
| Priority | High |
| Module | Accessibility |
| Origin | Genuine |
| Status | Open |
| Found in | https://www.saucedemo.com, Chrome (Chromium), 2026-11-05 |
| Test user | `standard_user / secret_sauce` |
| Failed test cases | TC-086, TC-087 |

## Steps to reproduce
1. Log in as standard_user
2. Press Tab repeatedly from the top of the products page (40 presses are enough to pass every control)
3. Watch which controls receive focus, then focus the cart icon by script and press Enter or Space

## Expected result
The cart link receives focus in the Tab order and Enter opens the cart (WCAG 2.1 success criterion 2.1.1 Keyboard, level A).

## Actual result
Tab goes through the menu, sort, every product link and button, but never reaches the cart icon. It is an <a role="button" data-test="shopping-cart-link"> with no href and no tabindex. Pressing Enter or Space on it (focused by script) does nothing. A keyboard-only shopper cannot open the cart, so cannot check out. The automated axe scan reported no violation for it. Found while writing the automated keyboard test, after the first manual keyboard pass had missed it.

## Evidence
Browser alert or behaviour with no screenshot; reproduce with the steps above.

> Impact if real: shoppers who cannot use a mouse (motor disabilities, screen-reader users) cannot complete any purchase. A blocker for a core flow and a legal risk in many countries. Logged as if found in a real product. The practice shop has no server behind its login, so this is how it is built, but a real shop with this behaviour would have the stated impact.
